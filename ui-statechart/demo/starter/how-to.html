How to use the FOAM starter

Four files, plus the framework one folder up. You edit one of them. No install, no build.

1. Run it

  1. Open a terminal inside the folder above this one (demo/), so the page can reach the framework file.
  2. Run: 
    python3 -m http.server 8000
    (any static file server works; double-clicking the page mostly works too, but some features need a server).
  3. Open http://127.0.0.1:8000/starter/.

2. What each file is

  • ../foam-bin-3.js (one folder up): the whole framework in one file. Do not edit.
  • index.html: loads the framework, loads your app, and has one tag: <foam class="starter.App">. That tag means "create this class and put it here".
  • app.js: your code. A model (a Todo has a title, a due date, a done flag) and a view (a form, a button, a table). Edit, save, reload.
  • tools/build-bin.mjs: rebuilds the framework file from a FOAM3 checkout. Only if you want a newer FOAM. Ignore at first.

3. Things to try, in order

  1. Add a property to Todo: { class: 'Int', name: 'priority' }. Reload. The form and the table both grew. You wrote no HTML.
  2. Change class: 'Date' to class: 'DateTime'. Reload. Different input.
  3. Change the seed rows in init().
  4. Make add refuse empty titles differently: edit isEnabled.
  5. In the browser console: foam.lookup('starter.Todo').create({ title: 'x' }). Every class you declare is reachable by name.

4. The ideas you just used

  • Model: foam.CLASS({...}) declares a class from data. Properties carry a type, so FOAM can draw inputs, table columns, and validation from the same declaration.
  • DAO: a collection with put, find, select, remove. In memory here. The same calls work against a server or a browser database later; only daoType changes.
  • View: foam.u2.Element. start()/end()/add() build the page. Passing a property (upper case, this.TODO) adds that property's own view.
  • Reactivity: the table watches the DAO, the button watches the title. Nothing polls, nothing re-renders by hand.
