How to use these pages

These pages are drawings you can click. Each one shows the steps something can be in (a screen, a record) and which step can come next. Clicking changes nothing real. Close the tab and nothing happened.

Opening the folder you were sent

  1. Unzip the folder.
  2. Double-click index.html. It opens in your browser. That is the front door: it lists every page with a one-line description.
  • The drawing tool loads from the internet. Without a connection the page opens but the drawing stays blank.
  • If a page stays blank in your browser, see If double-click does not work below.

If double-click does not work

The fallback is a small web server. It needs Python. Check first, so nothing crashes:

  1. Open a terminal inside the unzipped folder (Mac: Terminal; Windows: right-click the folder, "Open in Terminal").
  2. Type this and press Enter: 
    python3 --version
    On Windows, if that says it is not recognised, try py --version.
  3. You see a version (for example Python 3.12.4): you are good. Run 
    python3 -m http.server 8767
    (or py -m http.server 8767 on Windows), then open http://127.0.0.1:8767/index.html. Press Ctrl+C in that terminal to stop it.
  4. You see "command not found" or "not recognised": your computer cannot run the server. Stop here, do not run any other command. Go back to double-clicking index.html: the folder is built to work straight from disk, and the server is only a spare. If the page still stays blank, tell whoever sent you the folder.

Reading any drawing

  • Cards are steps (the code calls them states). Boxes around cards are groups: steps that belong together.
  • Arrows are allowed moves. No arrow between two cards means that move cannot happen.
  • Solid blue, thick border = where you are now.
  • Dashed blue = one click away.
  • Amber = the card under your mouse and the cards it connects to. Everything else fades so the arrows stand out.
  • Greyed = you cannot get there from where you are.
  • Hover anything for a tooltip: what the step means, whose turn it is, how long they have, where in the code it lives.
  • Click a card to move there. If the move is not allowed, the message line says why in words.
  • Every colour also has a border style or a symbol, so the page still makes sense printed in black and white.

The three kinds of page

1. Design spike (a screen being designed). The design fills the top of the page. The dark Spike controls strip above it switches sample data or layouts; it is not part of the design. The tabs below carry their status in the label: Try this round is the list of things to click and check, Statechart draws every step and move of the design, Ask the expert lists open questions, Legend and Log explain what you see and what just happened. A disabled button should say why next to it (the worked examples show a clock icon and Why not yet).

2. Walker (title ends in read-only walker). One machine per tab, drawn as a row of steps. Click the next step to move. ↩ back undoes one move. ⟲ reset goes back to the start. [guard] on an arrow means a rule in the code decides whether that move is allowed; where the page can read the rule, it shows the rule's own refusal text. Open legend under the drawing for the colour key.

3. Conversation (two parties, one exchange). Left side, blue and right side, pink are the two parties. Pick a story to replay a known sequence: play takes the next step, ↶ undo and ↷ redo step back and forward, ⟲ reset returns to the start with the story still chosen. The right column lists what happened, newest first, each row naming the code that does it. Open legend, sources and caveats to see what is wired in code versus assumed.

What these pages are for

They are throwaway drawings made to settle design questions by clicking instead of arguing. The page is scaffolding; the write-up it points at (the Based on line on the front door) is the record. If something looks wrong, say so. That is the point: the drawing changes before any real screen gets built.

Nothing here writes to any system. Refreshing resets a walker or a conversation.
